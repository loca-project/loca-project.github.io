# 0033. AI 検索はブラウザで埋め込みモデルを動かし、検索語をタグに読み替える

- 状態: 採用
- 日付: 2026-09-26
- 関連: [0014](0014-タグを人にしか書けない情報に絞る.md)（決定 7: AI にタグを付けさせない）、[0010](0010-書き込みと認証にFirebase無料プランを使う.md)（請求先を前提にしない）

## 背景

移植元の Chronos MAP には、TensorFlow.js の Edge AI 検索（`services/edgeAi.ts`）と、Gemini API を使う AI の品質管理の画面があった
（どちらも未移植。Edge AI 検索は 2026-09-22 に TensorFlow ごと削除した。T30）。
Loca は請求先を前提にせず、ADR 0014 で「AI にタグを付けさせない。検索語をタグに読み替えるだけ」と決めている。
マーカー検索は語の一致だけで、「紅葉」と入れても季節「秋」の動画には当たらなかった。

Loca は日本語と英語の両方が対象（利用者の判断）。モデルは最軽量より精度を優先する（利用者の判断）。

## 候補の比較

公表値（MTEB の公式の結果。同じ文章を英語と日本語に訳した課題の平均）と、Loca の試験問題での採点。

| モデル（圧縮版） | 大きさ | 公表値 英語 / 日本語 | Loca の 1 位の正解 日本語 / 英語（90 問・ラベルだけ） |
|---|---|---|---|
| **EmbeddingGemma-300m（4 ビット）** | 約 217 MB | 91.5 / 87.7 | 76% / 80% |
| bge-m3 | 568 MB | 78.5 / 76.7 | 71% / 62% |
| snowflake-arctic-embed-l-v2.0 | 570 MB | 80.7 / 78.6 | 58% / 67% |
| multilingual-e5-base | 278 MB | 76.2 / 75.0 | 56% / 62% |

日本語専用の Ruri（日本語の公表値は最も高い）は、英語が対象外なので候補から外した。

## 決定

1. **AI 検索は、ブラウザで埋め込みモデルを動かし、検索語をタグに読み替える。** タグを付けたり動画を判定したりはしない。
2. モデルは EmbeddingGemma-300m の 4 ビット版。ブラウザの WebAssembly 版の ONNX Runtime に無い処理（`GatherBlockQuantized`）を
   使わない版（`model_no_gather_q4`）を読む。精度は Node の 4 ビット版とほぼ同じ（未使用の問題で日本語 94% / 94%・英語 75% / 72%）。
3. タグは、ラベルに意味の説明を足した文（`src/core/constants/tagDescriptions.ts`。日本語と英語を並べる）と比べる。
4. タグの採り方（モデルごと。`src/adapters/semantic/models.ts` の `rule`）:
   - 1 位の近さが **下限 0.27** 未満なら読み替えない（地名・固有名詞を読み替えないため。地名 25 語の 1 位は最大 0.268）
   - 1 位から **幅 0.02** 以内のタグを **最大 3 つ** 採る
5. 結果は、語の一致の動画を先に、その後ろに読み替えたタグを持つ動画を並べる。結果パネルの題に「AI の読み替え: 秋」のように出す。
   地図検索では地名が見つかればその場所へ動かし、見つからないときだけ読み替えたタグの動画を出す（地名・語の一致を優先。T101）。
6. ~~既定は切（チェックボックスで入れる）~~ **2026-09-26 に改めた（利用者の判断。T101）: ページを開くと起動画面「Loca を起動しています... n%」の間に準備し、
   その後に地図と Firebase につなぐ。** チェックボックスは無い。起動画面には「ダウンロード」「Edge AI」の語を出さない（端末に何かを
   入れると不安にさせないため。利用者の判断）。止まったら諦めて Edge AI なしで起動を続ける（取得中に 45 秒進まない・取得後 120 秒で起動しない）。
   準備ができた = 起動して試しに 1 回計算できたこと。タグの説明文の埋め込みは前もって計算して `public/data/semantic-tags.json` に置く
   （スマホで 26 件を計算すると「準備中 100%」のまま止まった。`npm run semantic:vectors`）。部品約 590 kB とモデル・ONNX Runtime 約 240 MB
   （モデル約 217 MB・ONNX Runtime 26.9 MB）を読み、2 回目からはブラウザのキャッシュを使う。`?edgeai=off` で開くと準備しない（画面の確認用）。
   **データセーバー（`navigator.connection.saveData`）がオンの端末でも準備しない**（2026-10-02、利用者の判断。T105）。
   その端末では語の一致だけで検索する。`navigator.connection` は Chrome 系だけにあり、Safari・Firefox では準備する。
   実機（Pixel 10a・2026-10-02）: Chrome は Android のデータセーバーをオンにすると `saveData` が true になり、効いた。
   Brave は同じ設定でも true にならず、準備する（Chrome 系でもブラウザによって伝えない）。
7. 置き場所: モデルのファイルは Hugging Face から読む。ONNX Runtime（`.mjs` 53 kB・`.wasm` 26.9 MB）は自サイト（GitHub Pages）から配る
   （既定のままだと cdn.jsdelivr.net から読んでいた）。
8. **モデルは差し替えられるようにする。** 画面と検索の組み立ては `SemanticPort` だけを使い、モデルは `models.ts` の設定 1 件で決まる。
   差し替えの手順は `models.ts` の先頭に書いた（設定を足す → `npm run semantic:eval -- <名前>` で採点 → 下限と幅を決める → `ACTIVE_MODEL` を変える）。

## 採点（2026-09-26。`npm run semantic:eval`）

問題は `scripts/data/semantic-cases.json`。調整に使った問題 45 と、説明文を書く前に作った未使用の問題 32。どちらも日本語と英語を 1 問ずつ。

| 項目 | 結果 |
|---|---|
| 1 位の正解（未使用の問題） | 日本語 30/32（94%）・英語 23/32（72%） |
| 1 位の正解（調整に使った問題） | 日本語 41/45（91%）・英語 40/45（89%） |
| 読み替えた問題（154 問中） | 97 問。採ったタグに正解がある 94/97（97%） |
| 地名を読み替えない | 25/25（100%） |
| 実ブラウザ（`/ui-check`） | 「紅葉」「autumn leaves」→ 秋の 5 件、「鹿児島県鹿屋市串良町」→ 読み替えず 0 件。初回の読み込みは約 28 秒（この PC。T101 より前の、検索のときに読む方式で） |

## 検討した代替案

- **Actions で動画側の埋め込みを作り、ブラウザは検索語だけを変換する**: 精度は上がりうるが、ブラウザの重さは同じで作る量が最も多い。
  利用者がブラウザでモデルを動かす案を選んだ。
- **Actions がモデルで「検索語 → タグ」の対応表を作り、ブラウザは表だけを読む**: 軽いが、表に無い語は扱えない。同上。
- **最軽量の日本語専用モデル（ruri-v3-30m・37 MB）**: 英語が対象外。1 位の正解も 49%（52 問）と低い。却下。
- **語の一致の結果を出さず、AI の結果だけにする**: 地名や動画の題では語の一致のほうが正確。却下。

## 結果

良くなること:

- 「紅葉」「夜景」「drone footage」のような語で、タグを持つ動画が見つかる（日本語・英語）。
- 地名・固有名詞では AI は働かず、関係のない動画を出さない。
- モデルは設定 1 件と採点のコマンドで差し替えられる。

悪くなること:

- **データセーバーがオフの端末では全員、初回に約 240 MB を読む**（モバイルの通信を含む。T101 で既定に改めた。オンの端末は読まない。T105）。地図が出るのは準備の後になり、この PC で約 18 秒。
  スマホ（Pixel 10a）では初回約 60 秒、2 回目約 10 秒で、「桜」→ 春の読み替えも出た（2026-10-02、利用者の実機。T102）。
  2026-09-26 にスマホで「準備中 100%」のまま止まったのは、事前計算と時間の上限で直った。
- 英語の正解率（72%）は日本語（94%）より低い。英語の多義語（hot spring の spring を季節と取るなど）に弱い。
- 読み替えるのはタグだけ。題や現地メモの意味は見ない（語の一致だけ）。
- 初期読み込みの JS は 257 kB（上限 260 kB。T101 でチェックボックスを外して 2 kB 減った）。
- モデルの配布元（Hugging Face）に稼働の保証は無い。読めないときは語の一致の結果だけを出す（理由はブラウザのコンソールに出し、画面には出さない）。
- 起動の見張りが諦めても、取得そのものは止めない（中止の仕組みが無い）。止まった端末で通信が続くかは未確認。

## 確かめ方

- `npm run check` の `tests/core/semanticSearch.test.mjs`（下限・幅・並べ方）・`edgeAi.test.mjs`（止まったら諦める・事前計算がモデルと説明文に合う・準備しない端末（データセーバー・`?edgeai=off`））と、
  verify の「AI 検索の部品の import は src/adapters/semantic/ のみ」。
- モデルを変えたら `npm run semantic:eval`・`npm run semantic:vectors` と、実ブラウザでの確認（読み込み・読み替え・地名で 0 件・ONNX Runtime を外部から読まない）。
