# 0016. 参加の循環を「撮影リクエストへの回答」を軸に作る

- 状態: 採用（各施策はタスクごとに詳細を決める。2026-09-26 改訂。ADR 0031）
- 日付: 2026-09-24
- 関連: [0014](0014-タグを人にしか書けない情報に絞る.md)、[0015](0015-地図フィルタを画面下に常設する.md)、[0010](0010-書き込みと認証にFirebase無料プランを使う.md)

## 背景

マーカーは人が増えないと増えず、マーカーが増えないと人が来ない。
一度参加した人が、また戻ってくる理由（循環）を設計に組み込む必要がある。

### 調査（2026-09-24）

| 観察 | 出典 | Loca への示唆 |
|---|---|---|
| 生成 AI コンテンツへの反発と「実在の人・実体験」の重視。YouTube は 2026-05 から写実的な AI 動画に自動でラベルを付ける | Sprout Social・Hootsuite の 2026 年トレンド、TechCrunch 2026-05-27 | 「現地で人が撮った」を Loca の看板にする |
| バイラルよりコミュニティ。SNS が検索の入口になっている | 同上 | 少人数でも回る「頼む→応える→感謝」の小さな輪を作る |
| 日本では利用者参加型の聖地巡礼マップが相次ぐ（2026-03 開始の例あり）。訪問記録やブックマークで「自分だけのマップ」を作らせる | PR TIMES（みんなでつくる聖地巡礼マップ）、ろかまっぷ。 | 自分の足あとを残せる形は参加の動機になる |
| 場所のリストを友人と共有するアプリ（Beli・Corner）が伸びている | Beli・Corner の公開情報 | 絞り込んだ地図を URL で共有できるようにする |
| 感謝の通知は投稿者の継続率を上げる（Wikipedia の Thanks）。一方、ポイント・レベル型（Google Local Guides）は量を追わせ、質の低下と「ただ働き」の批判がある | Wikipedia/OSM の議論、Deng 2026（Big Data & Society） | 点数より「感謝」と「役に立った実感」を返す |

## 決定

循環の中心を、Loca 固有の**撮影リクエスト**に置く。

```text
見る ──→ 撮ってほしい（撮影リクエスト。ログインだけで参加できる）
 ↑                        │
 │                        ↓
共有リンクで        近くの撮影者が「このリクエストに応える」で投稿
新しい人が来る           │
 ↑                        ↓
 └── 投稿者に「ありがとう」が届く ←── 依頼者に「動画が届きました」
```

| 施策 | 担う段 | タスク | 優先 |
|---|---|---|---|
| リクエストに動画で応える（紐づけ、依頼者へのお知らせ、熱量が戻る。ADR 0028） | 頼む→応える | T43 | P2 |
| いいねを「ありがとう」として投稿者に届ける | 感謝 | T29 | P2 |
| 絞り込みと選択中のマーカーを URL で共有 | 共有 | T42 | P2 |
| 撮影者本人のバッジ（チャンネル連携）と自分の投稿一覧 | 投稿者の見返り | T26 | P2 |
| （2026-09-25 追記）撮影者本人のバッジは出さず、公開プロフィールに YouTube チャンネルのリンクを出す（ADR 0029） | 投稿者の見返り | T55 | P2 |
| ~~合成メディア申告の動画を除外~~（2026-09-25 取り下げ。API で申告を読めない。0014 の追記） | 実写の看板 | T44 | — |
| ~~足あと（投稿した都道府県の地図）~~（2026-10-02 棄却。利用者の判断: 投稿者で絞れば地図で分かる） | 自分だけのマップ | T45 | — |
| ~~特集（管理者が作る期間限定のテーマ。例: 秋の夜）~~（2026-09-26 棄却。利用者の判断） | 季節ごとの呼び戻し | T46 | — |
| 新着の RSS 配信（Actions で生成） | 戻ってくる入口 | T47 | P3 |

制約（0010）: Cloud Functions が使えないので、お知らせはプッシュではなく**サイト内の表示**にする。
ログイン時にブラウザが自分宛ての変化を読み取って出す。

## 採らないもの

- **ポイント・レベル**: 量を追わせ、質とタグの正確さが落ちる。
- ~~投稿数の順位（投稿数はランキングの基準にしない）~~（2026-09-26 改訂。利用者の判断で、ユーザーのタブに投稿数・再生数・いいね・撮影リクエストの並びを出す。ADR 0031）
- **AI による自動タグ付け・自動投稿**: 人が付けた情報という価値を損なう（0014）。
- **外部 SNS への自動投稿**: 別のトークンと運用が要る。必要になったら相談する。

## 結果

- 撮影リクエストに「応えた動画」との紐づけが増える（ルールとエミュレータのテストが要る。ADR 0013 の方式に従う）。
- 閲覧者を投稿者に、投稿者を YouTube チャンネルへ送る流れが Loca の見返りになる。

## 確かめ方

T43 完了後、依頼者と投稿者の 2 アカウントで「頼む→応える→届きました→ありがとう」が本番で一巡する。
