# 0011. 地図と地名を国土地理院に統一し、予備を持たない

- 状態: 置き換え済み（[0032](0032-地図と地名をOpenStreetMapに統一する.md)。2026-09-26、住所検索が応答しなくなったため）
- 日付: 2026-09-23
- 置き換え: [0003](0003-地図エンジンは-MapLibre-を既定にする.md) のタイルとジオコーディングの部分（MapLibre は継続）

## 背景

地図まわりは 3 つの提供元に分かれていた。

| 機能 | 提供元 | 予備 |
|---|---|---|
| 地図タイル | OpenFreeMap | 背景色だけの地図 |
| 座標 → 都道府県・市町村 | Nominatim | 県庁所在地からの最近傍（都道府県のみ） |
| 地名 → 座標 | Nominatim | 都道府県名だけ解決 |

Google Maps と Geocoding API は、無料の範囲の利用でも請求先アカウントが必須で使えない（[0010](0010-書き込みと認証にFirebase無料プランを使う.md)）。
代わりを探す中で、国土地理院のサービスが GitHub Pages から直接使えることを確かめた。

Loca の対象は日本国内だけで、必要な粒度は市町村までである。

## 調査結果（2026-09-23 実測）

`Origin: https://loca-project.github.io` を付けて呼び出した。

| サービス | URL | キー | CORS | 位置づけ |
|---|---|---|---|---|
| 地理院タイル（淡色地図） | `cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png` | 不要 | `*` | **公式**。出典の明示のみで申請不要 |
| 逆ジオコーダ | `mreversegeocoder.gsi.go.jp/reverse-geocoder/LonLatToAddress` | 不要 | `*` | **非公式**（地理院地図のための API） |
| 住所検索 | `msearch.gsi.go.jp/address-search/AddressSearch` | 不要 | `*` | 同上 |
| 市町村コード表 | `maps.gsi.go.jp/js/muni.js`（1,920 件・約 114KB） | 不要 | `*` | 同上 |

非公式の 3 つについて、国土地理院は「地理院地図からの利用を主目的としており、長期的な提供や
仕様の維持は保証しない」としている。

実測でわかった挙動:

- 淡色地図はズーム 2〜18。z0・z1 は 404。
- 逆ジオコーダは市町村コードを返す。北海道は `01101` のように先頭 0 付きだが、
  市町村コード表のキーは `1101`。**数値として照合する。**
- 海上と県境未定地（富士山頂）では `{}` が返る。
- 住所検索は候補を関連度順に並べない。先頭を採ると「東京タワー」が札幌市東区になる。

## 決定

**地図タイル・逆ジオコーディング・住所検索をすべて国土地理院に統一し、予備の実装を持たない。**

1. 地図は MapLibre GL JS ＋ 地理院タイル（淡色地図）。スタイルはコードで組み立てる（`maplibreStyle.ts`）。
   出典「地理院タイル」を地理院タイル一覧へのリンク付きで表示する。
2. 座標 → 地名は、逆ジオコーダの市町村コードを市町村コード表で引く。
   政令指定都市の区は落とし、市の名前にする（従来の粒度に合わせる）。
   コード表に無い新しい市町村でも、コードの先頭 2 桁から都道府県までは引く。
3. 地名 → 座標は住所検索 API。候補は次の順で選ぶ。
   - 行政区画名（都・道・府・県・市・区・町・村で終わる）: 都道府県から始まる正式表記 → 完全一致
   - それ以外: 完全一致 → 都道府県から始まる正式表記
   - どちらも無ければ部分一致 → 先頭
4. 取り込みスクリプト（`scripts/lib/enrich.mjs`）も同じ API と同じ照合方法にする。
5. 失敗はそのまま利用者に伝える。タイルを 1 枚も読めないときは、メニューの「公開データの状態」に表示する。

削除したもの: `nominatim.ts` `offline.ts` `prefectureCentroids.ts`、`GeocodePort.providesCity`、
`VITE_MAP_STYLE_URLS`、背景色だけの代替地図。

## 検討した代替案

- **OpenFreeMap ＋ Nominatim のまま**: 動いてはいた。ただし提供元が 2 つに分かれ、
  Nominatim は 1 秒 1 回の制限と、市町村の返し方が地域ごとにばらつく問題があった。
  日本の行政区画に正確なのは国土地理院のほう。却下。
- **国土地理院を本命、既存を予備に残す**: 予備を持つ必要は無いと判断した。
  予備の分だけ実装と検証の対象が増える。却下。
- **行政区域データ（国土数値情報）を自サイトに置いて判定する**: 外部依存は最小になるが、
  データの加工と更新の手間がかかる。非公式 API が止まったときの移行先として残す。

## 結果

良くなること:

- 地図と地名の提供元が 1 つになった。API キーも請求先も要らない。
- 市町村の判定が行政区画のコードに基づくので、県境付近でも正確になった。
- 東京 23 区の `province` 欠落のような、Nominatim 特有の補正が要らなくなった。

悪くなること:

- **逆ジオコーダ・住所検索・市町村コード表は非公式で、予告なく変わりうる。**
  予備が無いので、止まれば地名の取得と地名検索が使えなくなる（地図の表示と閲覧は続く）。
- **海上と県境未定地では地名を取得できない。** 登録画面は地名なしで続行し、取り込み側も空で通す。
- 同名の地名が多いもの（「清水寺」は 16 件）は、どれに移動するかを保証できない。
- 日本の範囲外は、ズームを上げると地図が表示されない（淡色地図の配信範囲）。

## 確かめ方

`node tmp/test-gsi.mjs`（ワークスペースの `tmp/`）が実 API を相手に、アプリ側と取り込み側の両方を検査する。
2026-09-23 時点で 15 件中 15 件 OK。`npm run smoke` で地図タイルが取得されることも確かめた（18 枚）。
