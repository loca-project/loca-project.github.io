# 0006. ランキングの基準を Loca 内の指標に変える

- 状態: **廃止**（2026-09-24、[0017](0017-YouTube-Data-APIとFirestoreへの書き込みはActionsから行う.md) で置き換え。T25 で元の要件の基準に戻した）
- 日付: 2026-09-22

> 置き換えた理由: 代替案 3「Data API をバッチ側でだけ使う」を、請求先なしで使えると確かめたうえで採った（ADR 0017）。
> キーはブラウザに配らず Actions の Secrets にだけ置く（2026-10-24 以降、調べもののスクリプト用の例外あり。0017 の追記）ので、この ADR が避けたかった「サイトから Google API を呼ぶ」ことにはならない。

## 背景

元の要件はランキングを **YouTube の再生数の降順**とし、
フィルタに**動画の投稿日**と**再生時間**を使っていた（要件 4.1 / 4.2）。
これらは YouTube Data API v3 でしか取得できない。

Google API の利用を廃止したため、取得手段を実測で洗い直した。

| 手段 | タイトル | チャンネル | サムネ | 再生数 | 投稿日 | 再生時間 |
|---|---|---|---|---|---|---|
| YouTube oEmbed（採用） | ○ | ○ | ○ | **×** | **×** | **×** |
| i.ytimg.com 直リンク | － | － | ○ | － | － | － |
| Piped / Invidious（非公式） | ○ | ○ | ○ | ○ | ○ | ○ |

非公式 API は **4 インスタンス中 1 件しか応答しなかった**（403×2 / 525×1）。
ToS 上もグレーで、基盤にできない。

## 決定

ランキングとフィルタの基準を、**markers.json だけで計算できる指標**に置き換える。

| 元の要件 | 現在 |
|---|---|
| 再生数の降順 | 登録件数の降順（同数なら新しい順） |
| 地域別＝再生数 | 地域別＝都道府県ごとの登録件数 |
| チャンネル別＝再生数合算 | チャンネル別＝登録本数 |
| 機器別＝再生数 | 機器別＝組み合わせごとの登録件数 |
| 動画投稿日フィルタ | Loca への登録日フィルタ |
| 動画の長さフィルタ | 削除 |
| インフォウィンドウの再生数 | 削除 |

`MarkerData` からも `viewCount` / `publishedAt` / `duration` /
`ytLikeCount` / `commentCount` を削除した。取得できない項目を型に残すと、
いつか埋まるという誤解を生むため。

## 結果

良くなること:

- 外部 API に依存しないので、ランキングは常に正確で、表示が遅れない。
- 「よく見られた動画」ではなく「よく記録された場所」を示す指標になり、
  地図サービスとしての趣旨には合っている。
- 自己申告や推定値が混ざらない。

悪くなること:

- **人気順という軸が失われた。** 動画の質を測る手掛かりがサイト内に無い。
- 登録件数は投稿者の偏りをそのまま反映する。1 人が大量投稿すると歪む。
- 元の要件 4.1 / 4.2 からの逸脱であり、要件書は注記付きで維持している。

## 代替案

- **投稿者が手入力**: 投稿日と再生時間は入力できるが、再生数は変動するので無理。
  自己申告の検証もできない。却下。
- **Actions で非公式 API から補完**: 要件は維持できるが、応答率 25% で
  ToS 上もグレー。壊れやすい基盤を運用に入れたくない。却下。
- **Data API をバッチ側でだけ使う**: 技術的には成立するが、
  「Google API の利用を廃止する」という決定に反する。却下。
